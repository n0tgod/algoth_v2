# Контекст проекта

Читать в начале каждой сессии. Этот файл — память проекта между сессиями: у ассистента её нет, у репозитория есть.

**Файл короткий намеренно** (разделён 2026-09-06 по просьбе владельца: к тому дню он дорос до 1.08 МБ — около 200 тысяч токенов на каждую сессию и каждый вызов агента). Здесь живут правила, решения, **состояние на сегодня** и **уроки**. История по этапам — `docs/memory/` (десять срезов, читаются по указателю, не подряд), хронология — `docs/journal/`, карта кода — `docs/MAP.md`. **Сюда не дописывают ход работы:** «Состояние на сегодня» переписывается по месту, урок общего свойства добавляется одной строкой, всё остальное — журнал. Предел размера держит `tools/safety_check.sh` (48 КБ; осознанный рост — `ALLOW_BIG_MEMORY=1`).

**Линия работы одна — `main`.** Новая сессия: `git fetch origin main && git checkout -B main origin/main`, пушить `git push -u origin main`. Сервер развёрнут на `main` и тянет её же. Перед КАЖДЫМ коммитом сверять `git log`: HEAD не свой — либо откат контейнера, либо законная публикация с сервера (смотреть родителя, не переписывать).

**Роль сессии** владелец называет первым сообщением («роль: дизайн»). Сессия обязана прочитать `docs/ROLES.md`, подтвердить роль одной строкой и держать её границы сама; роль не названа — дежурный. Коммит начинается с ярлыка роли: `[research]`, `[design]`, `[fix]`, `[live]`, `[duty]`.

**Журнал ведут все роли.** Одна запись на значимый шаг: решение владельца, результат прогона, меняющий картину, дефект класса «отказ, неотличимый от тишины», отвергнутая идея с доводом. Ход правок и зелёные тесты туда не идут — для этого `git log`.

**Команды на сервере ассистент запускает САМ, а не диктует владельцу.** SSH нет и не будет (наружу открыты только 80 и 443, измерено). Канал — очередь заданий через git (`jobs/README.md`): сессия коммитит `jobs/<имя>.job` одной строкой, дёргает `GET http://<сервер>/jobs-poke?k=<ключ>`, читает результат в `jobs/done/<имя>.log` через `git fetch`. Белый список: `run research/…py`, `restart-book` (деплой сборщика, страниц и цикла — он ОСТАНАВЛИВАЕТ цикл, сторож поднимает за 5 мин), `status`, `agents-run <роль>`, `cli-update`. Аргументы только латиница; задания идут ПАРАЛЛЕЛЬНО; ждать по `done/<имя>.log` (строка `конец:`), не по маркеру `.done`. Живой исполнитель (`tools/run_live.sh`) — только руками владельца, намеренно. Ключ страницы живёт в `out/token.txt` на сервере и в git не идёт — новой сессии его дают в первом сообщении.

**Защита от опасного коммита** — `tools/safety_check.sh`, ставится хуком `git config core.hooksPath tools/githooks` (разово в каждом клоне). Хук же перестраивает карту кода. Отказывает на удалении артефактов, маркерах конфликта, ключах, файлах больше 5 МБ и разросшемся ядре памяти. Проверка проверки: `bash tools/test_safety.sh`, `python3 tools/test_project_map.py`.

## Расстановка ролей

**Владелец проекта** — трейдер, не программист. Он задаёт гипотезы и оценивает результаты как трейдер; проверяет числа, а не код: сходится ли PnL, правдоподобна ли цена ликвидации, разумно ли поведение позиции; принимает все решения о риске и объёме работ.

**Ассистент** пишет код, статистику и инфраструктуру. Спецификации формулируются на человеческом языке именно потому, что владелец обязан иметь возможность их проверить. **Спека, которую владелец не может прочитать и оспорить, бесполезна.** Формулы приводить явно, решения обосновывать, а не декларировать. Команды владельцу — короткими строками, каждая завершённая, с `cd ~/algoth_v2 &&` в самой строке; деплой-блок называет КАЖДЫЙ процесс, чей код тронут.

## История: почему была первая версия и почему она умерла

Предыдущая платформа (`n0tgod/algoth_backend`, `n0tgod/algoth_frontend`) — около 54 000 строк, работающий продукт, заброшен в конце 2024 из-за исчерпания бюджета. Что убило проект: расползание объёма (фичи с интерфейсом и недописанным бэкендом); инженерная роскошь вместо продукта (4 000 строк кастомизации графика, соцсеть, 11 микросервисов — до первого платящего); отсутствие монетизации; ноль тестов на коде, считающем деньги; копипаста ядра (движок бэктеста форкнули, копии разошлись). **Глубина торгового движка** (усреднения, лестница тейков, трейлинг, таблица maintenance margin, re-entry cooldown) ошибкой не была — это невоспроизводимый за выходные актив. Ошибкой была очерёдность.

## Правила работы

1. **Ничего не строится, что не ведёт к ответу «есть ли эдж»** — пока фаза A не закрыта. Любая идея вне этого пути идёт в `IDEAS.md`. Не отвергается — откладывается.
2. **Одна задача в работе за раз.** Следующая не начинается, пока предыдущая не проверена владельцем.
3. **Каждый шаг заканчивается тем, что можно посмотреть** — числами, отчётом, работающим прогоном. Не «написал код».
4. **Спецификация — источник истины.** Сначала спека, потом реализация. Симулятор и живой бот считают по спеке 01 одинаково.
5. **Отрицательный результат — успех.** Стенд проектируется, чтобы убивать гипотезы, а не подтверждать их.

Ассистент по умолчанию с энтузиазмом сделает всё, о чём попросят. Ограничитель объёма — правило 1, и держать его нужно явно.

## Принятые решения

| Решение | Обоснование |
|---|---|
| Парная торговля как первая гипотеза | Не зависит от направления рынка; естественно обобщается до факторного остатка |
| Bybit — площадка исполнения | Binance для торговли недоступен; у Hyperliquid всего 232 инструмента и ~2 года истории |
| Binance — источник длинной истории | Архив с 2020, включая делистнутые; отношение между активами не зависит от площадки |
| Python для фазы A, Rust позже | Исследование — это итерации и статистика. Rust для боевого движка фаз C–D |
| Стенд фазы A — расходный материал | Его задача ответить на один вопрос, а не стать продакшеном |
| Универсум — на момент времени | 30.5 % перпов Bybit делистнуто; отбор «по сегодняшнему списку» есть отбор выживших |
| Плечо не является настройкой агрессивности | Задаётся неравенством безопасности; иначе ликвидация срабатывает раньше стопа |
| VPS в юрисдикции, откуда отвечает Bybit | Ставки funding Bybit существуют только в API; спека 02 §2.0 запрещает подменять их ставками Binance. Тот же сервер нужен фазам B–D |
| Латентность VPS не важна | Удержание позиции часы–дни. Машина рядом с биржевым движком не нужна |
| Перпы не на криптоактивы в универсум не входят | Базовый актив стоит в выходные, перп торгуется круглосуточно — календарная компонента. Ситуационным книгам торговать их МОЖНО (выход по уровню, решение 2026-08-13), книгам со сроком нельзя; стейблы отсекает флэт-фильтр |
| Монетизация: приватно; комиссия за результат как продолжение; подписка отвергнута | Ёмкость эджа $5–10 млн — каждый подписчик уменьшает сигнал, продавать его выгодно ровно когда он не работает. Строить после фазы C |
| Живые деньги только руками владельца, белый список книг `sit`/`sit_lo` | Решение «поднять торговлю» должно быть человеческим; фабрика список не расширяет |
| Единица показа — доллары и проценты, б.п. только в хранении | Решение 2026-09-02; два формата: движение со знаком (`pct`), порог без знака (`lvl`) |

## Чего не делать

- Не предполагать, что лимитная заявка исполнена, если цену коснулись (ошибка движка v1). Засчитывается сквозной проход принтов, не касание; стоп цену уровня не получает никогда.
- Не брать ставки funding с площадки, отличной от площадки исполнения.
- Не строить универсум из инструментов, торгуемых сегодня.
- Не менять пороги спек после получения результатов; не предъявлять лучшую ячейку сетки как результат (ошибка R5).
- Не расширять стоп, не усреднять против движения, не пересчитывать β на живой позиции — кроме DCA-семейства (спека 14), где усреднение вниз разрешено владельцем под забором §5.
- Не заводить вторую копию расчётного ядра. Деньги считает `research/s8_loop/trades.py`, и только он.
- Не подменять «не измерено» нулём: пропуск — прочерк с названной причиной.
- `git add -A`, `rm -rf` по данным, `git checkout -- файл` для отката — запрещены (`docs/DATA-SAFETY.md`).

## Фазы и этапы — не путать

Фаз пять и они про зрелость: **A** исследование, **B** paper trading, **C** живой микро $1–2k, **D** масштаб $10–20k, **E** продукт. Этапы живут **внутри** фазы и называются по гипотезе: A0–A4 (пары), R1–R6 (остаток), F1–F4 и S1–S4 (carry), L0–L5 (каскады), T1–T4 (лента), M1–M5 (обучаемый сигнал), E1–E4 (ядро бота), V1–V3 (турнир политик), D1–D4 (первые секунды), X1–X4 (живое исполнение), Z1–Z3 (скрины), W1–W3 (волны), D0–D9 спеки 14 (DCA). **Мы всё ещё в фазе A**: ни одна гипотеза не прошла критерии целиком. Живое исполнение X3 было замером МЕХАНИКИ, а не переходом в фазу C.

## Уроки, переживающие гипотезы

Каждый стоил прогона, суток или денег; каждый уже повторялся хотя бы раз.

**Отказ и тишина**
- **Отказ обязан быть неотличим от исправности НЕ.** Молчаливый ноль, прочерк без причины, «блок есть» на пустом блоке, лог, который никто не читает, — всё это выглядит работой. Ошибка идёт в статус и на страницу; тревога, кричащая всегда, перестаёт быть сигналом.
- «Не измерено» ≠ ноль: пропуск — прочерк с названной причиной. Нулевой шум, нулевой объём, пустой состав — не безопасность, а отсутствие меры.
- Признаком результата служит содержимое, а не утверждение: существование файла, дельта прогона, число строк, свежесть — все четыре уже врали (A2 `build.py`, L2, лига, склады).
- Прогон длиннее минуты печатает прогресс, пишет состояние файлом, публикует отчёт САМ (`publish.sh` — часть прогона) и запускается отцепленно (`setsid nohup`). Каталог артефактов создаётся до счёта; редирект лога — тоже каталог.
- Вердиктовая фраза выводится из числа, а не стоит рядом; число в прозе страницы стареет молча.

**Нули, пороги, меры**
- Пороги и сетка объявляются до прогона; лучшая ячейка после просмотра — ошибка R5. Судится правило отбора, а не победитель. Право на итерацию одно.
- Нуль обязателен и обязан быть честной формы: перестановка меток, сдвиг во времени, случайный момент, суррогат зигзага, случайные корзины ТЕХ ЖЕ размеров у дискретного признака. Калибровочная пара (найти подсаженное, молчать на шуме) — иначе сломанная загрузка неотличима от «эффекта нет».
- Контроль — одновременная кросс-секция; медиана — статистика, не портфель (хеджировать об неё нельзя); медиана и среднее печатаются оба — расхождение знака есть подпись короткой волатильности (F, Z1, всплеск).
- Единицы: спред «на ногу» против круга «на пару ног», доли против б.п., `fwd` против пути — ошибка единиц ловилась пять раз; потолок с идеальным знанием будущего считается ПЕРВЫМ — он закрывает направление за вечер.
- Ошибка Sharpe не зависит от частоты ребаланса; наблюдений столько, сколько независимых периодов (перекрытие раздувает t втрое); канарейка в таблице признаков меряет независимость.
- «Спасёмся мейкером» закрыт парой замеров (стресс и тишина): пассивный вход есть смена выборки со сменой знака.
- Урезать можно то, что отдаёшь, но не то, на чём считаешь: счёт — функция от ВСЕЙ истории.
- Колонка «без лучшего имени / без трёх лучших дней» обязательна: концентрация переворачивает знак.

**Код и проверки**
- Одно ядро: вторая копия формулы, списка книг, карты семейств, правила стороны — однажды расходится (список книг жил в восьми местах; проверка версии правил журнала — в шести, и замер издержек сложил все версии). Каждая дорога до показа проверяется отдельно.
- Подставной артефакт обязан выглядеть как живой: поля, которых живой писатель не пишет, дрожание, живые даты, живой масштаб — восемь случаев холостых проверок из-за фикстур.
- Отрицательный контроль обязан сперва доказать, что подделка легла (`assert` на литерал, копия файла — не `git checkout`), и ронять именно названную проверку; ожидание берётся форматом самой страницы, а не по памяти о правиле; `.pyc` врёт в обе стороны — свой каталог байткода на прогон.
- Правка скорости, меняющая числа, есть другая мера — ускорение сверяется бит в бит; память считается составом до счёта, рядом с записью, которую не докачать.
- Тест, чьё имя обещает больше, чем исполняет, хуже отсутствующего; новый тест ищется в выводе по имени; после скриптовой правки смотреть, легла ли она.
- Записанный урок не защищает новый модуль сам собой — память работает только там, куда её перенесли кодом (хуком, тестом, инвариантом).

**Данные и площадка**
- Замороженные ряды, дыры, метки времени: окна задаются во ВРЕМЕНИ, а не в номерах точек; «точка есть» ловит не всё; обратная волатильность без пола — замороженный ряд в новом костюме (пол из самого сечения).
- Время денежного события: вход занимает деньги в момент решения, выход возвращает в секунду события, порядок — целая секунда; цена выхода не из прошлого. Семь дефектов кассы — все про это.
- Площадка отдаёт данные по текущему состоянию (справочник, комиссии, тиры, интерес) — снятые контракты пусты, и это класс ограничения, а не сбой.
- Список не-крипто отстаёт от каждой волны листингов; правило мерится, а не ведётся списком, где это возможно.
- Ряд площадки, скачанный однажды, стареет молча: сборщик, возобновляющийся по существованию файла, ничего не продлевает — покрытие окна печатается числом ДО вердикта (funding A1: 0 % на журнале книг, ряды кончились за месяц до него).

**Процесс**
- `git add -A` и `rm -rf out` уже теряли артефакты; `publish.sh` не пишет удалений; конфликт на артефакте решается в пользу прогона.
- Контейнер песочницы откатывает рабочее дерево — перед каждым коммитом `git log`; правки в scratchpad, возврат копией.
- Деплой не закончен, пока `status` не показал процесс; `restart-book` убивает идущее обучение; задания очереди параллельны.
- Тяжёлый прогон рядом с циклом убивает не себя, а ЦИКЛ (OOM выбирает по-своему, трассировки не оставляет, буфер stdout гибнет с SIGKILL): предел памяти и самоостанов — в самом прогоне, лог строчно, `dmesg` — в диагностике.
- Объяснение, живущее на одной странице, не защищает соседнюю; каждая страница объясняет свой предмет сама.
