# Механика a82dcf58 — двойник по ИМЕНИ: как прогнать и что читать

Вопрос механики: **чьи это деньги — выбора модели или часа рынка.**
Каждому гейтованному лонгу журнала листов ставится двойник — случайное
имя из строки ТОГО ЖЕ ЧАСА, только крипто, не гейтованный выбор, из того
же дециля суточной σ; двойнику пересаживается геометрия выбора (смещения
рунгов долями цены входа, доля тейка, веса, плечо, ставка тира), и
меняется только имя с его ценовым путём.

## Порядок

1. **Калибровка — первой.** Она идёт на синтетике той же дорогой
   (`core`), считает секунды и отвечает на вопрос «а меру-то видно?»:

   ```
   cd ~/algoth_v2 && nice -n 19 .venv/bin/python \
       research/mech_a82dcf58/run_twin.py --calibrate --no-publish
   ```

   Код возврата 0 — калибровка годна (подсаженный ход найден, на шуме
   молчит, подделка ЛЕГЛА и это проверено числом). Код 2 — негодна, и
   тогда боевой прогон запускать незачем: сломанное чтение баров
   двойника выглядит в точности как «выбор работает».

2. **Смоук** — дорога от журнала листов до отчёта на малом населении.
   Читает настоящий журнал (~880 МБ в памяти), поэтому уже требует
   свободной памяти:

   ```
   cd ~/algoth_v2 && nice -n 19 .venv/bin/python \
       research/mech_a82dcf58/run_twin.py --stride 40 --draws 20 \
       --no-publish
   ```

3. **Боевой прогон.** Отцепленно, один поток, `nice 19`:

   ```
   cd ~/algoth_v2 && setsid nohup nice -n 19 .venv/bin/python \
       research/mech_a82dcf58/run_twin.py \
       > research/mech_a82dcf58/out/run_twin.log 2>&1 &
   ```

   Публикует отчёт сам (`tools/publish.sh`), каталог `out/` создаётся до
   счёта, состояние пишется файлом `out/state-1m.json` после каждого
   символа, прогресс — в лог не реже чем раз в 30 с.

## Чего прогон стоит

Два прохода по записи принтов (`research/b1_book/out/trades`, 6.4 ГБ на
2026-09-09), и второго не избежать: децили σ считаются по сечению часа
ЦЕЛИКОМ, то есть σ нужна у всех ~700 кандидатов каждого часа, а имена
двойников известны только после подбора. Проход 1 меряет σ и заодно, пока
бары символа в памяти, собирает геометрию и руку S его выборов; проход 2
идёт снова по символу и считает всех его двойников всех розыгрышей.

Измеренная скорость чтения — около 2–3 МБ/с сжатых принтов на этой
машине (BTCUSDT 3 суток за 4.4 с, TUTUSDT — за 37 с), то есть **около
45 минут на проход** плюс минуты на симуляции. Ожидание полного прогона —
**2–2.5 часа**, и это больше, чем «≤ 2 ч» заявки; число печатается
отчётом по факту (`secs`), а не берётся отсюда.

σ кладётся в кэш на символ (`.cache_sigma/`, ключ — версия меры и
`BACK_H`), поэтому ПОВТОРНЫЙ прогон первого прохода почти не стоит.
Кэш в git не идёт.

**Память.** Пик даёт чтение журнала листов (`legs_from_sheets`, ~880 МБ);
дальше сечения сжимаются в списки имён, и рабочий размер — сотни
мегабайт. Прогон отказывается стартовать, если не влезает рядом со
сборщиком (`mem_guard`, порог 0.85 доступной), и печатает пик по факту
(`peak_rss_mb`). Ключ `--no-mem-guard` — только для отладки.

## Ключи

| ключ | зачем |
|---|---|
| `--limit N` | первые N выборов (описывают неделю тишины — для дороги, не для чисел) |
| `--stride K` | прорежение через K: население лежит в трёх сутках, и прорежение честнее лимита |
| `--draws K` | розыгрышей (умолчание 100, меньше `MIN_DRAWS` = 20 — отказ) |
| `--seed N` | зерно числом |
| `--mmr own` | считать двойника по ЕГО тиру, а не по тиру выбора (ячейка вердикта — `pick`) |
| `--calibrate` | калибровочная пара на синтетике |
| `--no-cache` | не читать и не писать кэш σ |
| `--no-publish` | не публиковать отчёт |

## Что читать в отчёте

`out/TWIN-1m.md`. Порядок чтения — порядок дешевизны убийц:

1. **Измеримость.** Доля пар «позиция × розыгрыш», у которых двойник
   нашёлся и имеет бары. Ниже 80 % — вердикт ТОЛЬКО по измеренным, и
   число названо.
2. **Убийца 1** — медиана И среднее руки S против 95-го процентиля книг
   двойников. Главный, и по seed заявки самый вероятный.
3. **Убийца 2** — парная разность S − T (медиана и среднее обязаны
   совпасть знаком И по позициям, И по суткам; интервал парного
   бутстрапа обязан не накрывать ноль).
4. **Убийца 3** — дневная форма при одной кассе ($10 000, билет $25, одна
   позиция на имя): медиана дня, худший день, укус.
5. **Убийца 4** — колонка «без 3 лучших суток».

Диагностика (вердикта не выносит): T1 — двойник без подбора σ, разность
T1σ − T1 есть цена выбора волатильности; T2 — тот же двойник СО СВОЕЙ
геометрией; отдельный счёт выборов без структурной лестницы. **Предъявлять
лучшую руку запрещено:** ячейка вердикта одна — T1σ.

## Что нарочно НЕ сделано

- **Издержки не снимаются** (как в D2). Они одинаковы у S и у двойника по
  построению — та же лестница, то же плечо, тот же срок, — и пару не
  двигают. Абсолютные числа рук поэтому брутто, и это сказано в отчёте.
- **Кандидатом пула механика не становится** и правилом вылета не
  судится: она выносит вердикт о девяти живых бумажных DCA-книгах, а не
  заводит десятую. Эффективного N живых кандидатов не трогает.
- **Шорты не считаются.** Заявка о лонгах базовой ячейки D2/D3; зеркало —
  отдельный замер.
- **Тир двойника** берётся от ВЫБОРА (`MMR_FROM = "pick"`), потому что
  заявка говорит «меняется только имя с его ЦЕНОВЫМ ПУТЁМ», а ставка тира
  путём не является. Доля пар, у которых своя ставка отличалась бы,
  печатается числом; `--mmr own` считает вторую версию тем же кодом.

## Проверки

```
cd ~/algoth_v2 && .venv/bin/python research/mech_a82dcf58/test_twin.py
cd ~/algoth_v2 && .venv/bin/python \
    research/mech_a82dcf58/controls_check.py research/factory/out/build.json
```

Первая — сюита (26 проверок, ~5 с). Вторая — машина негативных
контролей: каждая подделка из `build.json` применяется к копии файла,
сюита обязана упасть, и упасть ИМЕННО названной проверкой (24 подделки,
≈4 минуты; одна из них — снятый отказ при пустом населении — идёт вдесятеро
дольше остальных, потому что прогон после неё считает пустоту до конца).

Сюиту машина запускает НЕ своей копией запускалки, а приёмкой
(`runlog._run_tests`). Своя копия однажды уже разошлась с приёмкой: та
смотрит ПОСЛЕДНИЕ 4000 символов вывода, копия — весь, и `expect` вида
«ПРОВАЛ имя», стоявший в середине одиннадцатитысячного вывода, копию
устраивал, а приёмку нет. Отсюда же правило для `expect` в `build.json`:
там стоит ГОЛОЕ имя проверки, потому что итоговая строка сюиты
(`провалено N из M: имена`) печатается последней и в окно попадает
всегда.
