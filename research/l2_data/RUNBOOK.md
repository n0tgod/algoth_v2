# L2 — сбор данных для гипотезы 5. Инструкция для VPS

Этап L2 спеки 06. Собирает открытый интерес по всему крипто-универсуму
(архив Binance) и проверяет площадку исполнения. Отбора событий здесь нет
— сбор обязан быть тупым, любое правило, применённое при сборе, потом
невозможно ни изменить, ни измерить.

Порядок важен: шаг 2 строит выборку по манифесту шага 1.

**Правило публикации.** Каждый прогон пишет отчёт файлом в `out/`, а не
только на экран, и заканчивается командой `tools/publish.sh`. Прогон
идёт на сервере, а обсуждается в другом месте: пересказывать консоль
скриншотами значит терять числа и время. Ряды и журналы в git не идут —
это решают правила `.gitignore` этапа, а не команда публикации.

## 1. Открытый интерес по универсуму — Binance

Сначала пилот на трёх символах, чтобы убедиться, что сеть и права на
месте. **Окно у пилота то же, что у полного прогона** — сокращать его
нельзя:

```bash
cd ~/algoth_v2 && .venv/bin/python research/l2_data/oi_binance.py --limit 3
```

Занимает около полутора минут и собирает настоящие ряды, которые
полный прогон потом переиспользует.

Первая версия инструкции предлагала пилот на пяти сутках
(`--start 2025-03-01 --end 2025-03-05`), и это испортило первый полный
прогон: три символа остались с пятью сутками вместо 912, потому что
признаком готовности было существование файла, а не собранное окно.
Теперь окно запоминается в манифесте и сверяется, но короткий пилот
всё равно бессмысленен — он лишь заставит собирать эти символы дважды.

Затем полный прогон:

```bash
cd ~/algoth_v2 && nohup .venv/bin/python research/l2_data/oi_binance.py \
  --workers 24 > research/l2_data/out/l2_binance.log 2>&1 &
```

| Что | Сколько |
|---|---|
| Символов | 621 крипто-актив с историей Binance |
| Символо-дней | 362 784 (окно 2024-01-01 … 2026-06-30) |
| Трафик | ≈ 4 ГБ, на диск сырьё не кладётся |
| Итоговые ряды | ≈ 1.5 ГБ в `out/oi_binance/` |
| Время | 2–4 часа при 24 потоках |

Прогон **возобновляемый**: единица — символ, готовый `<SYMBOL>.npz`
пропускается. Перезагрузка сервера или обрыв связи не стоят ничего,
кроме одного недокачанного символа. Запись идёт через временный файл,
поэтому наполовину записанного ряда не бывает.

Следить:

```bash
cd ~/algoth_v2 && tail -f research/l2_data/out/l2_binance.log
```

**Что доложить по окончании:** последние 10 строк лога, то есть блок
`ИТОГ СБОРА`. В нём важны два числа — доля дней без файла и число
дублей по метке. Архив Binance уже ловили на дырах (месячные файлы
2022-02 и 2022-04), и если доля пропусков заметная, это находка, а не
мелочь.

## 2. Площадка исполнения — Bybit

Два вопроса, оба обязаны быть закрыты до дорогой части L3: какое у
Bybit соглашение о метке и насколько глубока его история интереса.

```bash
cd ~/algoth_v2 && .venv/bin/python research/l2_data/oi_bybit.py --probe
```

Занимает минуты. Печатает две таблицы:

1. **Глубина истории.** Сколько суток назад отдаёт эндпоинт
   `/v5/market/open-interest` на шаге 5 минут и на часовом. Это предел
   площадки, а не наш выбор, и он задаёт период, на котором вообще
   возможно сравнение площадок.
2. **Соглашение о метке.** Профиль связи изменения интереса с объёмом
   по сдвигам −2…+2. Пик на 0 означает снимок на начале интервала
   (известен на метке), пик на +1 — на конце (известен на метке плюс
   шаг). Для Binance замер дал **пик на +1**, и вход из-за этого
   сдвинут на пять минут.

**Что доложить:** обе таблицы целиком. От первой зависит, имеет ли
смысл шаг 3 вообще; от второй — правило момента решения на Bybit.

Если глубина позволяет, дальше выборка символов и сбор:

```bash
cd ~/algoth_v2 && nohup .venv/bin/python research/l2_data/oi_bybit.py \
  --collect --sample 40 > research/l2_data/out/l2_bybit.log 2>&1 &
```

Выборка строится по манифесту шага 1: символы сортируются по медианному
открытому интересу и прореживаются равномерно, чтобы накрыть весь
диапазон размеров. Сравнение площадок на одних мажорах ничего не
сказало бы о хвосте универсума.

**Полного обхода Bybit по универсуму не делается.** Критерий §9.1
спеки требует доли общих событий между площадками, а для доли выборки
достаточно. Полный обход оправдан только если Bybit станет основным
источником, а спека этого не предполагает.

закрывается в L3 отсечением 30 дней, а не при сборе.

## 5. Чего на этом шаге НЕ происходит

Ни одного числа о доходности. L2 — это только данные; отбор событий,
контроли и нули идут в L3, а вердикт — в L5. Разделение соблюдается
намеренно: в A4 перестановочный тест обесценил результат месячного
прогона, и с тех пор дешёвая проверка стоит **перед** дорогой частью, а
не после.
