# Зонд сетапов — есть ли ситуация, устойчивая по всем книгам и рукам

Вопрос владельца (2026-08-24): «есть ли у нас сетапы, которые
стабильнее всего отрабатывают по всем нашим моделям/книгам».

Зонд, а не гипотеза: вердикта по направлению он не выносит и правил не
предлагает. Отвечает на один вопрос и называет, чего ответ не значит.

## Что считается

«Сетап» сделки — **доминирующее семейство признаков в разложении
вкладов этого прогноза** (`setup` в записи выбора). Это ЧТЕНИЕ
прогноза, а не выбранная стратегия: модель одна на все ситуации.

Мера — **превышение над своей же ячейкой**: медиана нетто семейства
минус медиана ВСЕХ сделок той же книги и руки. Без этого семейство
большинства (`book` — 61 % размеченных сделок) выглядело бы лучшим
сетапом в любой прибыльной книге.

Единица — базисные пункты нетто ПОСЛЕ издержек. Деньги не годятся: у
книг разный капитал и разные правила размера.

Ярлык берётся **на решение** (имя, час, сторона) большинством копий:
книги ранжируют одно сечение, и одно решение попадает в несколько
книг (замер 2026-08-24: 5098 строк лиги на 3770 решений, рекорд —
семь копий). Нетто решения — среднее по копиям.

## Пороги (объявлены до прогона, менять нельзя)

- ячейка (книга × рука × семейство) измерена при `n ≥ 30`;
- семейство измерено при `≥ 100` решениях и `≥ 4` измеренных ячейках;
- «устойчивый сетап» — шесть условий разом: доля ячеек с положительным
  превышением `≥ 2/3`; медиана и среднее нетто решений `> 0`; среднее
  `> 0` и без лучшего имени; превышение выше 95-го процентиля нуля 2;
  одинаковый знак превышения в обеих половинах истории.

## Нули

- **нуль 2 (главный)** — перемешивание ярлыков между РЕШЕНИЯМИ,
  1000 перестановок, зерно 20260824. Структура повторов сохраняется
  целиком, рвётся только связь «ярлык ↔ исход».
- **нуль 1 (диагностика)** — перемешивание внутри ячейки. Повторов не
  сохраняет и потому систематически мягче; разрыв двух планок и есть
  цена дублирования решений между книгами.

Судится ВЕЛИЧИНА превышения, а не доля ячеек: при сильном
дублировании доля насыщается — тот же набор решений под перемешанным
ярлыком даёт согласие всех ячеек тоже. Найдено тестом на синтетике до
прогона на живых данных.

## Запуск на VPS (минуты; читает только журналы книг)

```bash
cd ~/algoth_v2 && git pull
```

```bash
cd ~/algoth_v2 && mkdir -p research/probe_setups/out
```

```bash
cd ~/algoth_v2 && nice -n 19 .venv/bin/python research/probe_setups/setups.py
```

Отчёт публикуется прогоном сам: `out/SETUPS-report-1m.md`.
Выключить публикацию — `--no-publish`; своё имя артефакта — `--tag`.

Тесты (в песочнице): `python3 research/probe_setups/test_setups.py` —
восемь блоков, включая сквозной смоук с настоящими каталогами книг.

## Как читать

- **Семейство прошло все шесть условий** — есть ситуация, которая
  отрабатывает лучше средней сделки СВОЕЙ книги, и это не объясняется
  ни повторами решений, ни одним именем, ни половиной истории. Дальше
  разговор про гейт: торговать только такие часы.
- **Условия провалены на `null`** — превышение есть, но такое же даёт
  перемешивание ярлыков. Значит семейство — ярлык, а не сетап.
- **Провалено `wo_top`** — работает не сетап, а одно имя. Это уже
  переворачивало знак у четырёх групп лиги.
- **Провалено `halves`** — эффект был в одной половине истории и
  исчез; на нашей длине записи это обычный исход, а не аномалия.
- **Ни одно семейство не измерено** — записи мало. Число решений на
  семейство стоит в таблице; ждать надо календаря, а не пересчёта.

## Чего зонд не отвечает

Семейство — чтение вкладов, а не исполненное правило. Даже устойчивое
превышение НЕ означает, что можно «торговать только этот сетап»: гейт
изменит состав сделок, а значит и сами вклады. Проверять это придётся
книгой с объявленным гейтом, как проверялась книга низкого RR.
