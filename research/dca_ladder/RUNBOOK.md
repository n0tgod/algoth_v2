# D1 — потолок DCA-лестницы: как прогонять

Реплей читает хранилище A2 (только на VPS) и считает числа §8 спеки 14:
частота ликвидации на разрывах, руина (делистинг), бьёт ли лестница
наивное удержание, форма распределения. Ядро забора и симуляции —
`ladder.py` (закреплено таблицей §5), реплей — `run_dca.py`.

## Зависимости
`.venv/bin/python` (numpy, duckdb, pyarrow). Системный python их не несёт.

## Смоук (мал, быстро — проверить дорогу до store)
```
cd ~/algoth_v2 && .venv/bin/python research/dca_ladder/run_dca.py \
  --interval 1m --smoke --days-limit 3 --no-publish
```
40 имён, 3 даты входа. Печатает отчёт в stderr; в git не публикует.

## Полный прогон (отцепленно — читает ~600 имён, минуты)
```
cd ~/algoth_v2 && setsid nohup .venv/bin/python \
  research/dca_ladder/run_dca.py --interval 1m \
  > research/dca_ladder/out/run.log 2>&1 &
```
Публикует отчёт сам по завершении. Прогон, идущий из терминала в
переднем плане, умирает с сессией — только `setsid nohup`.

## Что читать
`out/D1-dca-1m.md` — вердиктовые числа; `out/D1-dca-1m.json` — сырьё.
Главное число — доля ликвидированных лестниц (§8.1, порог ≤ 0.5 %).
