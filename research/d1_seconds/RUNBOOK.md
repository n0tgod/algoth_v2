# D1 — как прогнать реплей на сервере

Гипотеза 7, спека 11. Этап **D1 — диагностика, вердикта нет**: он
отвечает, есть ли превышение над одновременной кросс-секцией и как оно
распадается с задержкой входа. Издержки и проскальзывание обходом
лесенки — D3.

## Где считать

Только на VPS: считается по записи стакана `research/b1_book/out/book/`,
а её нет больше нигде. Архива стакана не существует — историю нельзя
скачать, её можно только копить.

## Команда

Сначала короткий прогон — числа через несколько минут:

```bash
cd ~/algoth_v2 && git pull
mkdir -p research/d1_seconds/out
.venv/bin/python research/d1_seconds/run_d1.py --days 2 --jobs 2
```

Полный — **обязательно отцепленным от терминала**: он идёт час-полтора,
и закрытая сессия убивала бы его вместе с работой.

```bash
cd ~/algoth_v2 && mkdir -p research/d1_seconds/out
setsid nohup nice -n 10 .venv/bin/python \
    research/d1_seconds/run_d1.py --jobs 2 \
    > research/d1_seconds/out/d1.log 2>&1 &
tail -f research/d1_seconds/out/d1.log      # смотреть; Ctrl+C не убивает прогон
```

Вывод построчный, даже когда уходит в файл: это поставлено в коде, а не
ключом в команде — забытый ключ выглядел бы как зависание. На двенадцати
сутках прогон идёт **больше часа** (сутки читаются 5–8 минут), и молчание
в такой команде читается тревожно, поэтому смотреть надо не в терминал, а
в состояние.

Докуда дошло — видно и без терминала, в
`research/d1_seconds/out/D1-status-1m.json`: он переписывается после
каждых суток и несёт время, память и число событий. Упавший прогон
пишет туда же причину и публикует её — молчания быть не должно.

Отчёт публикуется **самим прогоном** — отдельной команды не нужно.
Отдельный шаг здесь уже стоил круга: прогон случился, отчёт лежал на
сервере, а в git не приехало ничего. Выключается `--no-publish`.

Частичный прогон (`--days 3`) пишет отчёт под своим именем
(`D1-report-1m-3d.md`) и имя полного не занимает: по содержимому они
неотличимы, и трёхсуточная диагностика встала бы в git отчётом этапа.

`--jobs` больше двух не ставить. На сервере одновременно работают
сборщик (его нельзя ронять), боевой цикл и ночной турнир; **запись —
единственное, что нельзя восстановить**, и ради ускорения реплея
рисковать ею незачем. Реплей идёт с пониженным приоритетом.

## Что он делает и сколько это стоит

Читает снимки книги посекундно, кладёт середину на секундную сетку,
находит падения на 3 и 5 % за 15 минут, считает сделку при пяти
задержках входа и трёх горизонтах и сравнивает с теми, кто в ту же
секунду не падал.

Дорого здесь чтение: в строке снимка лежит вся лесенка, а нужны три
числа. Поэтому разбор лёгкий — и он закреплён тестом на совпадение с
`json.loads` дословно. Порядок величин: около 24 ГБ книги на сегодня,
сутки читаются десятками минут, память по суткам порядка 1.5 ГБ.

**В сторож (`watchdog_book.sh`) прогон намеренно НЕ вписан.** Турнир
туда вписан, а этот — нет, пока не увидим на живых числах, сколько он
ест времени и памяти рядом с работающим сбором. Ночной прогон, который
однажды заберёт память у сборщика, стоит суток записи, а докачать её
неоткуда.

## Проверка события по ленте — до D2

Событие определено по середине стакана, а она падает и без единой
сделки: достаточно, чтобы сняли биды. Такой «отскок» есть возврат
котировки на место, торговать его нельзя ни при какой задержке.

```bash
cd ~/algoth_v2 && git pull
.venv/bin/python research/d1_seconds/tape_check.py --jobs 2
```

Считается по ячейке вердикта, кладёт события в три группы —
подтверждено лентой, только котировка, нечем проверять — и печатает,
где живёт превышение. Заодно меряет спред в момент события: вход платит
его половину, выход вторую, и это первый честный взгляд на исполнение.

Третья группа существует не для полноты: сделок в записи может не быть
по нашей вине, и «нечем проверять» — не опровержение. Если ВСЕ события
окажутся там, отчёт скажет «судить нечем», а не «направление закрыто».

## Что появится

- `out/D1-report-1m.md` — отчёт: покрытие, кривая распада по задержке,
  ячейка вердикта, условия §7, которые видны без издержек;
- `out/D1-events-1m.json` — те же числа машинно.

Оба уходят в git через `tools/publish.sh`.

## Как читать

1. **Сначала покрытие.** Требование §3 — не меньше 14 суток по 300
   символам. Пока записи меньше, отчёт честно пишет «НЕ выполнено», и
   любые числа ниже — предварительные.
2. **Потом ширину фона.** Фон тоньше 50 имён означает, что контроль не
   построен, а не что эффекта нет. В зонде возврата ячейка порога 2 %
   была пуста именно поэтому.
3. **Потом кривую распада.** Она обязана убывать с задержкой. Не
   убывает — сломана мера, а не рынок щедр (§7, условие остановки 2).
4. **И только потом величину** — и то помня, что это валовая: круг
   тейкера 11.7 б.п. на $10 тыс. стоит рядом справочно, а настоящее
   исполнение считается в D3 и будет дороже.

Предъявлять лучшую ячейку из тридцати запрещено спекой: ячейка вердикта
объявлена одна (падение 3 %, задержка 5 с, удержание 30 минут),
остальные — диагностика распада.
