# Потолок механики «смена интервала начисления funding»

Что это. Механика подана заявкой предлагающего и построена целиком:
событие — **первое начисление по укороченному интервалу** (8/4/2 ч → 1 ч)
на площадке исполнения, позиция — **лонг** против выталкиваемых шортов
при ставке < 0. Здесь лежит потолок: самый дешёвый расчёт, способный
закрыть направление до всякого строительства живой книги.

Нового сбора нет. Всё считается по уже собранному: ряды funding Bybit
(`research/a1_universe/out/funding`, 722 символа) и минутные бары
хранилища A2. Оба в git не идут, поэтому счёт — на сервере.

## Что уже проверено без прогона

```bash
cd ~/algoth_v2 && .venv/bin/python research/probe_fshift/test_fshift.py
```

26 проверок, среди них — тест на заглядывание в будущее с негативным
контролем (заведомо заглядывающий детектор обязан его провалить) и
калибровочная пара: подсаженный ход обязан находиться, на случайном
блуждании превышение обязано быть около нуля. Без второй половины пары
отрицательный результат не значит ничего — сломанная загрузка выглядит
ровно как «эффекта нет».

## Смоук: пять имён за квартал

Пишет артефакт под ОТДЕЛЬНЫМ именем и в git не идёт: по содержимому
смоук неотличим от настоящего прогона, а коммит F2 однажды уже подменил
артефакт этапа смоуковым.

```bash
cd ~/algoth_v2 && mkdir -p research/probe_fshift/out
cd ~/algoth_v2 && nice -n 19 .venv/bin/python \
    research/probe_fshift/run_ceiling.py --tag smoke --no-publish \
    --start 2026-04-01 --end 2026-07-01 \
    --symbols BLURUSDT,ORCAUSDT,GASUSDT,B3USDT,TUTUSDT
```

Смоук отвечает на один вопрос — работает ли дорога целиком, — и НЕ
отвечает на вопрос механики: на пяти именах кросс-секции нет (порог
`MIN_CROSS = 50`), и превышение там не измеряется вовсе.

## Полный прогон

```bash
cd ~/algoth_v2 && mkdir -p research/probe_fshift/out
cd ~/algoth_v2 && setsid nohup nice -n 19 .venv/bin/python \
    research/probe_fshift/run_ceiling.py --tag 1m \
    > research/probe_fshift/out/run.log 2>&1 &
```

Отцепленно (`setsid nohup`), потому что прогон длиннее минуты, а
прогон, умерший вместе с оборвавшейся сессией, снаружи неотличим от
«не запускали». Отчёт публикует сам прогон; `--no-publish` выключает.

Заданием очереди — то же самое одной строкой:

```
run research/probe_fshift/run_ceiling.py --tag 1m
```

## Что прогон стоит машине

Полной матрицы «символы × минуты» здесь нет вовсе: событий немного, а
от цены нужны ровно три момента на событие (идеальный вход, настоящий
вход, выход). Грузятся только эти минуты, сечение на якорь — вектор в
700 чисел. Матрица печатается числом до счёта вместе с доступной
памятью (урок D1: память считается СОСТАВОМ, а не на глаз), потому что
рядом идёт запись стакана — единственное необратимое в проекте.

## Как читать отчёт

`out/FSHIFT-ceiling-1m.md`, числа (а)–(г) в порядке дешевизны; каждое
закрывает механику само:

- **(а) плотность** ниже `ceiling.MIN_ACTIVE_SHARE` — форма по правилу
  вылета неизмерима, остальное считать незачем;
- **(б) превышение с идеальным входом** ниже круга нейтральной книги —
  закрыто; идеальный вход есть верхняя граница, настоящий только хуже;
- **(в) отношение к контролю 2** ниже 1.5 — смена интервала не
  добавляет ничего к уровню ставки, и это carry в новом костюме;
- **(г) ставка события далека от предела своего ряда** — посылка
  механики ложна.

Вердикт в отчёте выводится ИЗ ЧИСЕЛ, а не стоит рядом с ними
литералом: фраза, написанная руками, однажды противоречит своему же
числу.

## Чего потолок не считает

Связь дневных денег с живыми книгами пула. Её считает потолок фабрики
своими рядами (`research/factory/ceiling.py`), и ряд «сутки → нетто»
лежит в `out/fshift-ceiling-1m.json` ровно в той форме, в какой его
судит правило вылета (`pool.shape_why` → `stability.stats`).
