### 1.4 Схема файлов — вход для A2

Месячный CSV, 12 колонок. В файлах до 2025 года заголовка нет,
в поздних есть — загрузчик обрабатывает оба варианта.

| # | Колонка | Примечание |
|---:|---|---|
| 0 | `open_time` | мс, UTC — ключ времени |
| 1 | `open` |  |
| 2 | `high` | нужен для консервативной проверки стопа внутри бара |
| 3 | `low` | то же |
| 4 | `close` | цена сигнала: z считается на закрытии бара |
| 5 | `volume` | в базовом активе |
| 6 | `close_time` | мс |
| 7 | `quote_volume` | в USDT — основа фильтра ликвидности |
| 8 | `count` | число сделок — поле `trades` схемы раздела 2.3 |
| 9 | `taker_buy_volume` | агрессивные покупки |
| 10 | `taker_buy_quote_volume` |  |
| 11 | `ignore` | служебное, всегда 0 |

Целевая схема хранилища раздела 2.3 — `(symbol, time, o, h, l, c,
v, trades)` — покрывается полностью. `quote_volume` берётся сверх
неё: фильтр ликвидности раздела 2.1.1 нужно считать в долларах,
а не в единицах базового актива, иначе активы несравнимы.

### 2.2 Дифференциал между ногами

Парная позиция держит одну ногу в лонг, вторую в шорт, поэтому
платит не ставку, а **разницу ставок**. Распределение модуля
разницы по всем 258 840 парам универсума:

| Квантиль | Годовых |
|---|---:|
| 5 % | 1.5 % |
| 25 % | 7.9 % |
| 50 % | 19.7 % |
| 75 % | 44.4 % |
| 95 % | 123.2 % |

**Как это читать.** Дифференциал не является издержкой сам по себе:
знак зависит от того, какая нога в лонге, а направление задаёт
z-оценка, а не funding. При симметричном чередовании направлений
вклад в среднем гасится.

Существенно другое — величина и устойчивость. Разница такого
порядка сравнима с целевой доходностью раздела 8, а ставки
персистентны: актив с дорогим фондированием остаётся дорогим
месяцами. Значит у пары с устойчиво разным funding по ногам
возникает систематический денежный поток, знак которого задаётся
тем, в какую сторону эта пара обычно торгуется. Это измеримо и
не является шумом.

Отсюда открытый вопрос 12.4 спеки 01 — оставить funding только
издержкой или включить в критерий отбора пар — переходит из
теоретических в требующие проверки на данных. Окончательные числа
считаются по ставкам Bybit; эти показывают порядок величины.
