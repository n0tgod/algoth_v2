# Запуск сбора данных на VPS

Инструкция для владельца. Предполагает чистую Ubuntu LTS и ничего больше:
все сборщики написаны на стандартной библиотеке Python, ставить зависимости
не нужно.

## 0. Зачем вообще VPS

Из песочницы разработки закрыты торговые API — это геоблок по IP датацентра,
а не настройка прокси:

| Адрес | Ответ |
|---|---|
| `api.bybit.com`, `api.bytick.com`, `api.bybit.nl`, `api.byhkbit.com`, testnet | 403 CloudFront |
| `fapi.binance.com` | 451 |

Публичные архивы при этом открыты, и всё, что можно взять из них, уже
собрано без VPS. На сервер уходит **только то, чего в архивах нет**:

- **ставки funding Bybit** — существуют исключительно в API. Обходных путей
  нет: `premium_index` покрывает 11 инверсных контрактов,
  `kline_for_metatrader4` — 23 символа. Спецификация 02, раздел 2.0
  запрещает подменять их ставками Binance: при удержании 3–5 дней funding
  составляет значимую часть P&L, а ставки между площадками расходятся;
- справочник инструментов — шаг цены и объёма, минимальный нотионал;
- ставки комиссий базового тира.

Тот же сервер понадобится дальше: фаза B — paper trading 4–8 недель
непрерывно, фазы C–D — живой бот круглосуточно.

## 1. Выбор локации — до оплаты

### Близость к бирже роли не играет

Два независимых довода, оба проверяемые:

1. **Латентность не важна.** Удержание позиции 1–5 дней. Машина рядом с
   биржевым движком не нужна ни сейчас, ни в фазе D.
2. **«Рядом с Bybit» — величина, которой нет.** API стоит за CloudFront:
   в заголовках ответа видно `x-amz-cf-pop`, и при запросе из песочницы
   это был `JFK50`. Глобальный CDN отдаёт с ближайшего edge независимо от
   того, где ядро биржи. Для REST и архивов расстояние до Сингапура ни на
   что не влияет.

Хуже того, близость и доступность тянут в разные стороны: **Сингапур и
Япония — юрисдикции с регуляторными ограничениями у Bybit**, то есть
географически ближайшие локации как раз наиболее вероятные кандидаты на
403. Ставку на страну делать не нужно — нужно проверить.

### Проверка

Список разрешённых юрисдикций меняется без объявлений, поэтому единственный
надёжный способ — измерить. Тарификация почасовая, проверка стоит центы:

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://api.bybit.com/v5/market/time
```

- `200` — локация годится;
- `403` — гасите машину и берите другую.

Блокировка бывает не только страновой: диапазоны отдельных провайдеров
попадают под неё целиком даже в разрешённой стране. Поэтому проверять надо
именно ту машину, на которой будете работать, а не «страну вообще».

Проверить сразу всё, что нам нужно:

```bash
for u in \
  "https://api.bybit.com/v5/market/time" \
  "https://api.bybit.com/v5/market/instruments-info?category=linear&limit=1" \
  "https://data.binance.vision/" \
  "https://public.bybit.com/trading/"
do printf "%s -> %s\n" "$u" "$(curl -s -o /dev/null -w '%{http_code}' --max-time 20 "$u")"; done
```

Годится машина, где все четыре строки отвечают `200`.

## 2. Параметры машины

| | |
|---|---|
| Диск | 100–160 ГБ — свечи 1m по ~720 инструментам за 6 лет дают 15–30 ГБ в Parquet, сырые архивы ещё ~31 ГБ, плюс запас под тики выживших пар |
| CPU / RAM | 4 vCPU, 8 ГБ — если на машине будет работать Claude Code, брать 8, а не 4 |
| ОС | Ubuntu LTS, Python 3.11+ |

Диск — единственный параметр, который реально ограничивает выбор тарифа:
у большинства провайдеров 160 ГБ идут в комплекте с 4 vCPU и 8 ГБ RAM.
Где можно докупить блочное хранилище отдельно, дешевле взять младший тариф
плюс том на 100 ГБ.

### Кого смотреть

Цены меняются, проверяйте на сайте — здесь порядок величины.

| Провайдер | Локации без ограничений у Bybit | Почасовая | Комментарий |
|---|---|---|---|
| **Hetzner** | Германия, Финляндия | да | Заметно дешевле остальных при вдвое больших ресурсах. Разумный выбор по умолчанию |
| **Vultr** | Франкфурт, Амстердам | да | Много локаций, удобно перебирать при 403 |
| **DigitalOcean** | Франкфурт, Амстердам | да | Блочное хранилище отдельно — можно взять младший тариф |
| **Linode / Akamai** | Франкфурт, Амстердам | да | — |

Европейские локации предпочтительнее азиатских не из-за скорости, а из-за
регуляторного статуса: у Bybit есть лицензия MiCA и работа в EEA, тогда как
в Сингапуре и Японии их деятельность ограничивалась. Это соображение о
вероятности, а не гарантия — проверка из раздела 1 обязательна в любом
случае.

## 3. Установка

```bash
sudo apt update && sudo apt install -y git python3 tmux
git clone https://github.com/n0tgod/algoth_v2.git
cd algoth_v2/research/a1_universe
python3 test_universe.py          # 25 проверок, должно быть OK
```

### 3.1 Claude Code на самом сервере

Смысл не в удобстве. Пока ассистент работает из песочницы, API Bybit для
него закрыт, и всё, что требует живого API, приходится передавать вам
сборщиками и инструкциями. С сервера в разрешённой юрисдикции этот барьер
исчезает: ассистент видит те же данные, что и вы, и может проверять
пагинацию, разбирать пустые ответы и чинить сборщик на месте, а не вслепую.

```bash
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs
npm install -g @anthropic-ai/claude-code
claude
```

Первый запуск попросит авторизацию. На машине без браузера он печатает
ссылку — открываете её у себя на маке, входите в аккаунт и возвращаете код
в терминал. Альтернатива, если удобнее ключом:

```bash
export ANTHROPIC_API_KEY=...
```

Работать через `tmux`, иначе сессия умрёт вместе с ssh:

```bash
tmux new -s algoth        # начать
# Ctrl-b d                  отцепиться, всё продолжает работать
tmux attach -t algoth     # вернуться, в том числе с другого устройства
```

Долгие прогоны запускать внутри `tmux`, а не через `nohup`: так видно вывод
и можно вмешаться.

**Про доступы.** Ключи API Bybit держите в переменных окружения, а не в
файлах репозитория. Для сбора данных нужны права только на чтение —
торговые разрешения на ключе не включайте до фазы C.

## 4. Что запускать

Все сборщики возобновляемые: сетевые ответы кэшируются на диск, готовые
символы пропускаются. Обрыв связи не портит прогон — достаточно запустить
команду заново.

### 4.1 Данные Bybit — ради них и нужен сервер

**Сначала смоук-тест на одном символе.** Пагинация истории funding писалась
вслепую: из песочницы разработки API недоступен, проверить её там было не на
чем. Прогон по всему универсуму долгий, и упереться в ошибку на третьем часу
обидно.

```bash
python3 bybit_api.py --symbol BTCUSDT
```

Ожидаемое: порядка 6–7 тысяч записей за полный срок жизни инструмента, шаг
8 часов, без разрывов. Проверить глазами:

```bash
zcat out/funding/BTCUSDT.csv.gz | head -3
zcat out/funding/BTCUSDT.csv.gz | wc -l
```

Если записей сотни вместо тысяч — пагинация не дошла до начала истории,
и полный прогон запускать рано. Сообщите, поправлю.

Затем полный прогон:

```bash
python3 bybit_api.py
```

Собирает справочник инструментов и историю funding по всему универсуму.
Перед стартом сам проверяет доступ и при 403 объясняет причину, а не падает
с трассировкой.

Ставки комиссий требуют ключа API (только чтение, торговых прав не нужно):

```bash
export BYBIT_API_KEY=...
export BYBIT_API_SECRET=...
python3 bybit_api.py --with-fees
```

Без ключа шаг просто пропускается — числа из памяти не подставляются.

Ключ и секрет — **разные строки**, и секрет показывается один раз при
создании ключа. Если в `BYBIT_API_SECRET` попадёт значение ключа, площадка
ответит `Error sign` и напечатает строку, которую подписывала; строка
совпадёт с нашей, потому что дело не в формате запроса, а в секрете.
Скрипт ловит этот случай **до** сбора funding: иначе прогон обходит все
722 символа и падает на последнем шаге. Быстрая проверка, что переменные
видны и различны, без печати значений:

```bash
echo ${BYBIT_API_KEY:+key_set} ${BYBIT_API_SECRET:+secret_set}
[ "$BYBIT_API_KEY" = "$BYBIT_API_SECRET" ] && echo "СЕКРЕТ РАВЕН КЛЮЧУ"
```

Если секрет утерян — создать новый ключ, прав `read-only` достаточно.

### 4.2 Свечи Binance в полном разрешении

В песочнице 1m по всему универсуму не помещается: ~31 ГБ сжатого архива на
20 198 символо-месяцев. На сервере с диском 100–160 ГБ ограничения нет.

```bash
python3 binance_klines.py --interval 1m
```

Сверяет контрольные суммы каждого месячного файла и считает пропуски баров
внутри наблюдаемого диапазона. Идёт долго — запускайте под `tmux` или
`nohup`, прогон переживает обрыв ssh:

```bash
nohup python3 binance_klines.py --interval 1m > klines.log 2>&1 &
tail -f klines.log
```

### 4.3 Остальное уже собрано

Универсум на момент времени, история funding Binance и инвентаризация
свечей 15m лежат в репозитории — пересобирать не нужно. Обновить универсум
свежим срезом архива, когда понадобится:

```bash
python3 universe.py && python3 report.py
```

Сырые ряды в git не идут — это данные исследования, для них в разделе 2.3

```

```

```bash
git add out/instruments.json out/funding_summary.json out/klines_inventory_1m.json
git commit -m "feat(a1): данные Bybit и свечи 1m, собранные на VPS"
git push
```

## 6. Проверка, что всё сошлось

После прогона `bybit_api.py` в сводке не должно быть символов с нулём
записей funding у инструментов с длинной историей. Если такие есть — это
не сбой сети, а повод разобраться: либо инструмент жил слишком мало,
либо API отдаёт по нему пустоту, и тогда пара с этой ногой не может
участвовать в расчёте издержек.
