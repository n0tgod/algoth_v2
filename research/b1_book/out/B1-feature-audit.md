# B1 — аудит записи под обучение модели на стакане

Дата: 2026-08-01. Повод: решение владельца — модель гипотезы 6 обучать
в первую очередь на стакане (итерация §11 спеки 07, доступна после
8 недель записи: 4 на обучение, 4 на проверку). Пока идёт запись,
самое дорогое — её качество: каждый день записи не того сырья — минус
день из часов. Полосы BTC/ETH уже однажды неделю выглядели измерением,
не измеряя ничего.

## Что пишется (по коду `collect.py`/`book.py`, подтверждено живыми снимками)

- **Раз в секунду по 25 символам:** вся лесенка (`STORE_LADDER = 0` —
  все уровни; глубина подписки 50, у BTC/ETH 200), лучшие цена и
  размер обеих сторон, число обновлений книги за секунду, охват книги
  в б.п. (`reach_b`/`reach_a`), нотионал в полосах ±0.05/0.1/0.25/0.5 %.
- **Лента целиком** со стороной агрессора (соглашение проверено на
  архиве: 96 % принтов `Buy` двигали цену вверх).
- **Сырой поток изменений** — один символ (ARBUSDT).
- **Бумажные сделки** детектора: открытие и закрытие, с версией правил.
- Часы сжимаются атомарно при закрытии; обрыв стоит одной строки.

## Признак модели → сырьё → статус

| признак | сырьё | статус |
|---|---|---|
| глубина полос к своему прошлому | `bq/aq` раз в секунду | пишется; **нужна цензура по охвату** (находка 1) |
| дисбаланс сторон | `bq/aq`, лучшие размеры | пишется |
| спред, микроцена | `bid/ask/bid_sz/ask_sz` | пишется |
| частота «крупного» к своему прошлому | вся лесенка, 1 с | пишется (гейт B1 уже считает это живьём) |
| выедено против показанного | лента (числитель) + лесенка 1 с (знаменатель) | пишется; внутри секунды — только ARBUSDT (находка 2) |
| время жизни уровня | лесенка 1 с, уровень прослеживается по секундам | пишется |
| интенсивность обновлений | `upd` за секунду | пишется |
| funding / открытый интерес | B1 не пишет — и не должен: архив Binance и REST Bybit дают их задним числом | не дыра |

Сырьё для всех объявленных §11 признаков на диске есть. Дыр «пишем не
то» не найдено; найдены две границы измеримости.

## Находка 1: полосы цензурируются охватом книги — видно живьём

Лесенка фиксированной длины кроет у плотного инструмента мало базисных
пунктов, и полоса шире охвата равна полосе поуже — число есть,
измерения нет:

| символ | охват, б.п. | различимых полос из 4 |
|---|---|---|
| BTCUSDT (глубина 200) | ±4.3 | **1** — все четыре равны |
| ETHUSDT (глубина 200) | ±11 | 2 (±0.05 и ±0.1 %) |
| VELVETUSDT (глубина 50) | ±19 | 2 |
| SOLUSDT (глубина 50) | ±68 | 4 |

Глубже 200 площадка не отдаёт (`error:handler not found`, проверено при
постройке), то есть широкие полосы у плотных монет публичным потоком
**не существуют физически**. Охват пишется в каждый снимок — при сборке
признаков полоса шире охвата обязана становиться пропуском, а не
числом. Конвейер M1/M2 пропуски уже умеет: NaN — своя корзина модели.

## Находка 2: восполнение внутри секунды измеримо на одном символе

Знаменатель «выедено против показанного» на секундных снимках не видит
подставку, съеденную и восстановленную внутри одной секунды. Сырой
поток, который это видит, пишется только по ARBUSDT — расширять его на
всё сечение дорого (это самый тяжёлый вид данных) и не нужно для
признаков горизонтов от минут. Рекомендация: признаки строить на
секундной сетке, ARBUSDT оставить диагностикой величины недоучёта.

## Ширина сечения — главный рычаг измеримости модели

Модель кросс-секционная: ошибка Спирмена одного сечения ≈ `1/√(n−1)`.

| имён в сечении | SE сечения | SE среднего по 672 часовым сечениям (4 недели проверки) |
|---|---|---|
| 25 (сейчас) | 0.204 | 0.0079 — эффект 0.02 отличим на ~2.5σ, на грани |
| 50 | 0.143 | 0.0055 — ~3.6σ |
| 100 | 0.100 | 0.0039 — ~5σ |

Запас по железу есть: 25 символов = 50 тем, ~290 сообщений/с, книга за
все дни записи — 0.33 ГБ (проекция 8 недель на 25 символах — единицы
ГБ при 83 свободных). Ограничение — разбор JSON одним потоком;
расширять ступенями по 10–15 имён, после каждой смотреть
`last_msg_age_sec` и долю живых тем. **Состав списка — решение
владельца** (правило записано в шапке `absorb.py`).

## Часы записи

Годная запись идёт с момента двух починок — хранения (атомарное сжатие
часа) и глубины BTC/ETH. Первую дату годного часа назвать с сервера:

```bash
ls ~/algoth_v2/research/b1_book/out/book/SOLUSDT/ | head -3
```

Имя первого файла — начало отсчёта. 8 недель считаются от него; каждое
расширение списка символов заводит НОВЫЙ отсчёт только для добавленных
имён — старые 25 копятся непрерывно.

Полнота записи (доля секунд со снимком, дыры от перезапусков) считается
при сборке признаков из самих файлов — отдельный сторож не строится
(правило 1). Следствие уже сейчас: перезапускать сборщик только по
делу, каждый перезапуск — дыра в будущей обучающей выборке.

## Решения владельцу

1. **Расширять ли сечение с 25 до ~50 имён.** Рекомендую да, ступенями:
   это главный рычаг измеримости будущей модели, и работает он только
   вперёд — задним числом запись не появится.
2. Полосы плотных монет: оставить цензуру по охвату (рекомендую) —
   восстановление из сырого потока для всех имён не окупается.
3. Сырой поток: оставить одним символом (рекомендую).
