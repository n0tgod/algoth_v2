# algoth v2 — самообучающиеся торговые модели на крипто-перпах

Живой контур: **две модели — деревья (ML) и нейросеть (AI) — ежесуточно
переобучаются на собственной записи стакана Bybit** по всем крипто
USDT-перпам, соревнуются на одинаковых данных и ведут бумажные счета.
Всё написано с нуля на Python/numpy, без внешних ML-библиотек: код
обеих моделей — три сотни строк, которые можно прочитать целиком.

**Текущая фаза: A — исследование, гипотеза 6 (обучаемый сигнал).**
Задача фазы одна: честно ответить, существует ли устойчивый эдж, до
того как написана хоть строчка торгового бота. Отрицательный ответ —
такой же полноценный результат, как положительный, и стоит он на
порядок дешевле.

---

## Две модели

| | деревья («ML») | сеть («AI») |
|---|---|---|
| Код | [`research/m2_walkforward/gbm.py`](research/m2_walkforward/gbm.py) | [`research/s8_loop/nn.py`](research/s8_loop/nn.py) |
| Как думает | чек-лист вопросов с порогами | смешивание всех признаков с весами |
| Пропуск данных | своя NaN-корзина | подстановка + флаг «данных не было» |

Всё остальное у рук одинаково намеренно: признаки, цели, ежесуточное
walk-forward переобучение, канарейка на перемешанных форвардах,
бумажный счёт $1000 с тейкерскими издержками. Разница результатов
принадлежит способу обобщения, а не данным. Подробно простыми
словами — [`docs/two-models-explained.md`](docs/two-models-explained.md).

## Данные

Живая запись на VPS (~540 монет, все торгуемые крипто USDT-перпы):

- **стакан** — вся лесенка снимком раз в секунду;
- **лента** — каждая сделка со стороной агрессора;
- **funding, открытый интерес, базис** — раз в 5 минут;
- **ликвидации** — потоком, по сторонам;
- сырой поток изменений книги — по ARBUSDT (эталон внутрисекундной
  динамики; на все монеты его не хватит диска, а признаки модели
  считаются из секундных снимков).

Исторические хранилища (для контекста и сверок): свечи Binance 1m с
2020 года по 720 активам (Parquet, `research/a2_storage`), funding
обеих площадок, открытый интерес с 2024 (`research/l2_data`). Ряды в
git не идут — публикуются только код и отчёты.

## Признаки, цели, цикл

**50 объявленных признаков** (спека 08 §3): стакан и лента, формации
из практики владельца (зажим, наклонка, проторговка, место в
диапазоне), funding/интерес/ликвидации, время (час суток, день
недели, минуты до начисления), режим волатильности, ход BTC и своего
сектора, близость к круглому числу. Всё нормировано к собственному
прошлому монеты; список заморожен до итерации.

**Цели** — не только направление, но и путь: форвардный остаток к
рыночной волне плюс максимальный ход в пользу и против (MFE/MAE) на
горизонтах 1/4/24 часа — геометрия сделки учится на рыночных путях,
где наблюдений миллионы.

**Цикл** (`research/s8_loop/train.py`): каждый час — сводка записи,
раз в сутки — переобучение обеих рук; первой считается канарейка
(обучение на перемешанном будущем обязано давать ноль — иначе
конвейер течёт и веса не обновляются); каждый прогноз проверяется
фактом (живой вневыборочный IC), выборы помечаются **новизной**
(доля признаков вне диапазона обучения) и разбираются в мыслях
модели трейдерскими словами. Процессы держит сторож
(`tools/watchdog_book.sh`, cron + @reboot) — обрывы сети, падения и
перезагрузки переживаются без рук.

**Вердикт объявлен до наблюдения** (спека 08 §7): 500 непересекающихся
часовых сечений на проверочном отрезке, критерии из спеки 07 §8.
Страница и счета — наблюдение, не доказательство.

## Запуск: окружение

Сборщики ранних этапов обходятся стандартной библиотекой — так и
задумано. **Начиная с A2 нужны зависимости**, и системный `python3`
их не имеет:

| Этап | Что нужно |
|---|---|
| A0, A1 | стандартная библиотека |
| A2 | `pyarrow` |
| A3+ и вся аналитика | `duckdb`, `numpy` |
| B1 (сбор стакана), S8 (цикл) | `websocket-client`, `numpy` |

Окружение создаётся один раз и живёт рядом с репозиторием:

```bash
cd ~/algoth_v2
[ -d .venv ] || python3 -m venv .venv
.venv/bin/pip install -q numpy pyarrow duckdb websocket-client
```

Дальше **все прогоны идут через `.venv/bin/python`, а не через
`python3`**. Команда идемпотентна: если окружение уже есть, ничего не
пересоздаётся. Проверка на месте:

```bash
.venv/bin/python -c "import numpy, duckdb, pyarrow, websocket; print('зависимости на месте')"
```

Отчёты — исключение и зависимостей не требуют: числа лежат в
JSON-артефактах, `report.py` собирается любым `python3`.

## Запуск: сбор живых данных

Сборщик стакана — не прогон: он живёт неделями и пишет ряды на диск.

```bash
cd ~/algoth_v2
nohup .venv/bin/python research/b1_book/collect.py --http 8765 \
  > research/b1_book/out/collect.log 2>&1 &
```

Ключ `--http` поднимает **страницу наблюдения**: стакан, лента,
мысли и выборы обеих моделей, их счета, журнал. Ссылку с ключом
доступа сборщик печатает первой строкой журнала (`head -3
research/b1_book/out/collect.log`); ключ живёт в `out/token.txt` и в
git не идёт.

Проверить, что сбор жив:

```bash
tail -f ~/algoth_v2/research/b1_book/out/collect.log   # строка раз в минуту
cat ~/algoth_v2/research/b1_book/out/status.json       # состояние книг
```

Перезапуск после правки кода — **одной командой** (`TERM`, ожидание
настоящего выхода, обновление, запуск, проверка что процесс жив):

```bash
cd ~/algoth_v2 && tools/restart_book.sh
```

Текущий час пишется простым текстом и сжимается атомарно при закрытии
часа; испорченные архивы читаются разбором по членам. Перед первым
запуском — проверка пути записи без сети:

```bash
.venv/bin/python research/b1_book/collect.py --selftest
```

## Запуск: цикл обучения

Руками цикл не запускается — его держит сторож:

```bash
crontab -l    # */5 tools/watchdog_book.sh + @reboot
```

Сторож проверяет не «жив ли процесс», а **свежесть данных** и
поднимает и сборщик, и цикл. Обновление кода на сервере:

```bash
cd ~/algoth_v2 && git pull && pkill -f s8_loop/train.py   # сторож перезапустит
```

Если менялся состав почасовой сводки — пересвести хвост под новую
схему (поздняя строка часа побеждает):

```bash
.venv/bin/python research/s8_loop/summary.py --redo 36
```

Артефакты цикла — `research/s8_loop/out/model/`: манифест с
важностями и границами новизны, выборы (`picks.jsonl`), разборы
фактом (`review.jsonl`), мысли, счета обеих рук.

## Запуск: прогон и публикация одной командой

Прогон идёт на сервере, а обсуждается в другом месте, поэтому
результат должен оказываться в git сам:

```bash
cd ~/algoth_v2
tools/run.sh "сообщение коммита" research/<этап>/<скрипт>.py --ключи
```

Команда отвязывается от ssh, зовёт `.venv/bin/python`, публикует
только при успехе и пишет журнал в `<этап>/out/<скрипт>.log`.
`tools/publish.sh` — отдельно, когда прогон уже сделан и артефакты
надо опубликовать руками (только дозапись, удалений не фиксирует).
