# Спека 18 (черновик): дерево книг — режим → сторона → ветви правил

Черновик 2026-10-16 по решению владельца: «пересоберём архитектуру
деревьями: в корне Depth, Gated, Sigma, каждая разветвляется на Both,
Long, Short, дальше ответвления по правилам — пока охрана с разными %,
потом ещё что-то придумаем». Написано человеческим языком, чтобы
владелец мог оспорить каждое правило до того, как оно станет кодом.
Решения, которые ждут владельца, помечены **[решение владельца]** и
собраны в §9.

## 0. Что это НЕ отменяет

- **Ядро одно.** Деньги считает тот же код (`run_d6.ration`, `trades.py`,
  `costs.apply_to_rows`); дерево — адресация и показ, не второй счёт.
- **Код и пути не переименовываются** (решение 10.10 и 14.10): ключи
  книг `safe_h`, `pair_optimal` и т. п. остаются ключами журналов и
  кэшей. Дерево — объявленная поверх них карта.
- **Пороги объявляются до прогона.** Ветви охраны — 0 / 2 / 4 / 6 %,
  сетка названа сейчас и не расширяется по результатам (ошибка R5).
- **Витрина, не селектор.** Подпись «default» несёт решение владельца,
  а не лучший результат; рейтинг не выбирает ветвь (§4).

## 1. Дерево словами

```
Sigma            Depth            Gated              ← режим: источник плеча
├─ Long          ├─ Long          ├─ Long            ← сторона
│  └─ (одна ветвь: правил-вариантов пока нет)
├─ Short         ├─ Short         ├─ Short
│  ├─ guard 4 % · default
│  ├─ no guard
│  ├─ guard 2 %
│  ├─ guard 6 %
│  └─ guard 4 % + inverse 2 %   (с 17.10, только Short)
└─ Both          └─ Both          └─ Both
   ├─ guard 4 % · default
   ├─ no guard
   ├─ guard 2 %
   └─ guard 6 %
```

- **Корень** — режим, он же источник плеча: Sigma (6σ), Depth (2·d_max),
  Gated (глубина и гейт ≥ 4×). Имена — решение 14.10 (`rules.MODE_EN`).
- **Сторона** — Long (книги `sit`: `safe`/`optimal`/`aggr`), Short
  (`h24`: `safe_h`/`optimal_h`/`aggr_h`), Both (`pair_*`: обе на одном
  депозите).
- **Ветвь** — набор правил-вариантов. Сегодня одна ось — охрана рынком у
  короткой стороны: 4 % (действующее правило, `default`), без охраны, 2 %,
  6 %. У Long ветвь одна: осей ещё нет; когда появится первая (например
  пол капитуляции или срок), Long разветвится тем же способом.
- **Ветвь «4+2»** (владелец 16.10, после замера `inverse_guard.py`): у
  Short — прямая охрана 4 % плюс ОБРАТНАЯ 2 %: шорт закрывается по
  закрытию часа и тогда, когда волна рынка с входа упала на ≥ 2 %
  (`rules.WAVE_INV_GUARD_PCT`, `inv_guard_of`, слово выхода «рынок за
  нас»). Ключ — `_g4i2`, адрес несёт `inv: 2.0`. Это не новая ось сетки,
  а одна объявленная ветвь-кандидат: замер показал рост кассы оборотом,
  не исходом позиции, и выбор ячейки после просмотра (R5) — поэтому суд
  только записью вперёд с 17.10, без бэктеста в зачёт. У Both её нет.
- **Лист** — конкретная книга с депозитом и форматом размера: лист ×
  {100, 1k, 10k, 100k} × {compound, fixed}. Это те же ячейки, что сейчас.

## 2. Адрес книги

Каждая книга получает объявленный адрес:

| поле | значения | откуда |
|---|---|---|
| `mode` | `safe` / `optimal` / `aggr` (показ: Sigma / Depth / Gated) | `rules.mode_of(key)` |
| `side` | `long` / `short` / `both` | по семейству: `sit` → long, `h24` → short, `pair` → both |
| `branch` | список `{rule, value, default}`; у Long пустой | карта ветвей `rules.BRANCHES` |
| `key` | ключ книги в коде и журналах | прежний |

Ключи ветвей-сестёр: суффикс `_g<порог>` — `safe_h_g0`, `safe_h_g2`,
`safe_h_g6`, `pair_safe_g0`, … Основная книга суффикса не несёт:
`safe_h` и есть ветвь «guard 4 % · default». `mode_of` снимает суффикс
ветви так же, как снимает `_h` и `pair_`; `family_of` у сестры — семейство
основной книги. Это тот же приём, что у сестёр по формату размера
(`:fixed`), только на уровне ключа книги, потому что охрана меняет ИСХОДЫ
позиций, а не размер (урок: правило, меняющее исход, обязано менять
подпись кэша и журнал).

## 3. Запись и версии

- У сестры **своя запись**: журнал, кэш реплея, свод, страница. День
  рождения — день включения (`RULER_SINCE[key]`), до него — бэктест, с
  него — «вперёд». Версия правил у сестры — версия семейства основной
  книги: смена версии семейства касается всех ветвей разом (правило
  стороны одно), а своя ось ветви в версию не входит — она и есть ветвь.
- Основные книги не меняются: `safe_h` с охраной 4 % остаётся тем же
  ключом с той же записью, версия 7 / 13 от 16.10 стоит.
- **Ветвь 2 % наследует запись** (решение владельца 16.10: «по факту мы
  возвращаем всё, что было»): строки версии h24 5 / pair 11 основных книг —
  весь пересчёт и сутки записи вперёд 15.10 → 16.10 под охраной 2 % при
  нынешних остальных правилах — переносятся копией под ключ `_g2` и
  текущую версию семейства (`tools/branch_inherit.py`); `written_at`
  сохраняется, поэтому «вперёд» остаётся «вперёд». Исходные строки не
  трогаются; повтор переноса ничего не добавляет. День рождения ветви
  2 % — 2026-10-15, день тех версий; у ветвей 0 и 6 % — 2026-10-16.
  Запись вперёд под 2 % старше 15.10 перенести нельзя честно: до 15.10
  другие правила (не-крипто, шаг объёма) — она пересчёт у любой ветви.
- Сестра не вправе менять подпись кэша основной книги; кэш сделок без
  охраны (`run_short` до охраны) общий, охрана считается поверх —
  как в `guard_sweep`.

## 4. Показ и рейтинг

- **Каталог** — дерево: три корня; у корня — три стороны с числами листа
  `default`; у стороны — ветви. Выбор депозита, формата, учёта и окна —
  как сейчас, на весь каталог.
- **Рейтинг** (решение владельца 16.10 вечером, вместо предложенного):
  на главной странице — ВСЕ листья одним списком с сортировкой, как
  прежде, включая ветви; на каждой строке метки дерева — сторона и ветвь
  правил. Архитектурное разветвление режим → сторона → ветви — отдельная
  вторая страница («Tree»). Оговорка о выборе после факта остаётся в
  подвале каталога: лучшая строка списка после факта — лучшая ячейка
  сетки, а не стратегия.
- Подпись `default` стоит у ветви, которую выбрал владелец, с датой
  решения; при смене умолчания меняется подпись, запись ветвей не
  трогается.
- Страница книги у сестры такая же, как у основной; в шапке — адрес:
  «Depth · Short · guard 2 %». В «About» строка правила ветви словами
  (`plain` строится из карты — одно ядро).
- Подписка с ключом — на любой лист, в том числе на сестру: механизм
  общий (`intents.guard_exits` читает порог книги подписки). Живые
  деньги — только кнопкой владельца, как и прежде.

## 5. Что меняется в коде

Сервер (`algoth_v2`):
1. `rules.py`: `BRANCHES` (ось `guard`: 0/2/4/6, default 4), ключи сестёр
   в `H24_ORDER`/`PAIR_PARTS`/`RULERS` (генерируются из основной книги,
   не копируются руками), `WAVE_GUARD_PCT` по ключу, `RULER_SINCE`,
   `address_of(key)` → `{mode, side, branch, key}`; `mode_of` снимает
   `_g<n>`; `journal_of`/`artifact_of` знают сестёр через `family_of`.
2. `run_short.py`, `run_pair.py`: группы книг идут по `order_of(family)` —
   сестры попадают сами; проверка: число книг в своде = число ветвей ×
   сторон.
3. Свод (`/dca`, `/api/v1/pub/dca`): у каждой линейки поле `address`;
   отдельно `tree` — готовое дерево для каталога (корни → стороны → ветви
   с ключами книг), чтобы приложение не собирало его из суффиксов.
4. Страницы сборщика: список книг по дереву; у сестры подзаголовок ветви.
5. API аккаунтов: `strategies` отдаёт адрес; подписка на ключ сестры
   законна.

Приложение (`algoth_ios`, спека 16): каталог деревом (корень → стороны →
ветви), рейтинг по `default`, шапка книги с адресом. Поле `tree` свода —
источник; карта `BookName` остаётся запасом для режимов.

## 6. Цена

Книг у коротких и общих становится 6 → 24; расчёт охраны идёт поверх
общего кэша сделок (замер семи порогов — 8 минут), касса сестры — те же
секунды на книгу. Диск: журналы ×4 для этой части, десятки мегабайт.
Память: сестры считаются в той же группе, что основная книга, по одной
ветви за раз — пик не растёт вчетверо (проверить числом при первом
прогоне, предел 2400 МБ остаётся).

## 7. Этапы — каждый кончается тем, что можно посмотреть

- **T1 сервер:** карта ветвей, ключи сестёр, адреса, свод с `tree`;
  результат — страница `/dca-page` с 24 короткими и общими книгами,
  у сестёр подзаголовок ветви и запись с дня рождения.
- **T2 API:** `strategies` и `dca` отдают дерево; подписка на сестру.
- **T3 приложение:** каталог деревом, рейтинг по `default`, шапка с
  адресом; сборка в TestFlight.
- **T4 (позже):** первая ось у Long — отдельная спека и решение владельца.

## 8. Чего не делаем

- Не переименовываем ключи, пути и журналы.
- Не добавляем ветвь по результату прогона: новая ось — объявление до
  прогона, своя запись с нуля.
- Не выбираем `default` по лучшей ячейке: умолчание — решение владельца
  с датой.
- Не считаем в приложении: дерево и числа приходят с сервера.
