# С чего начинать сессию

Карта проекта. Читается за минуту, дальше — только то, что нужно роли.

## Порядок чтения

1. **`CLAUDE.md`** (корень) — память проекта: правила работы, история
   гипотез, состояние на сегодня, найденные дефекты и уроки. Она
   загружается сессии автоматически.
2. **`docs/ROLES.md`** — какая роль у этой сессии и чего она не трогает.
3. **`docs/DATA-SAFETY.md`** — сохранность данных. Читать до первой
   команды, которая пишет на диск.
4. **`docs/journal/`** — хронология: вопросы владельца, ответы, почему
   так и почему не иначе. Читать последний месяц, если нужен контекст
   недавних решений.

## Пять правил, которые нарушать нельзя

1. **Одно ядро.** Деньги считает `trades.py`, и только он. Вторая копия
   расчёта однажды разойдётся с первой — так умер движок v1.
2. **Отказ обязан быть виден.** Молчание неотличимо от исправности:
   ошибка идёт в статус и на страницу, а не только в лог.
3. **Правка скорости не меняет чисел.** Кеш, ускорение, урезание —
   только с проверкой, что результат тот же.
4. **Пороги объявляются до прогона.** Лучшая ячейка сетки, выбранная
   после — не результат, а подгонка.
5. **Данные класса A не восстанавливаются.** Перед любой командой,
   которая их касается, — `docs/DATA-SAFETY.md`.

## Ветки: одна линия

**Работа идёт в `main`.** До 24 августа 2026 весь проект жил во
временной ветке `claude/claude-md-stage-a1-pqrhnx` (581 коммит), а
`main` оставался на состоянии времён L1. Новый чат создаёт свою ветку
ОТ `main` — то есть получил бы проект полугодовой давности и пушил бы
туда, куда сервер не смотрит. Поэтому линия сведена в `main`, и это
теперь единственная линия проекта.

Новая сессия обязана убедиться, что работает с `main`, а не со своей
временной веткой:

```bash
git fetch origin main && git checkout -B main origin/main
git log --oneline -1        # последний коммит обязан быть свежим
```

Пушить — в `main` (`git push -u origin main`). Сервер развёрнут на
`main` и тянет её же.

## Как ассистент запускает команды на сервере

Прямого доступа нет: из песочницы наружу открыты только 80 и 443,
порт 22 режет политика, на 443 — терминирующий TLS-прокси. Читать
сервер можно (страница наблюдения на 80, ключ параметром `k=`),
запускать — нет.

Поэтому **очередь заданий через git** (`jobs/`, см. `jobs/README.md`):
сессия коммитит `jobs/<имя>.job` с одной строкой, сторож на сервере
подхватывает её в течение пяти минут, выполняет из белого списка и
публикует результат в `jobs/done/<имя>.log`. Владельцу копировать
команды не нужно.

```
run research/probe_turn/turn.py --tag 1m     # прогон зонда
restart-book                                  # перезапуск сборщика
status                                        # диск, процессы, статусы
```

Что нельзя: произвольные команды, `rm`, работа с ключами, скрипты вне
репозитория. Правила исполняет `tools/jobs.sh`, проверяет
`tools/test_jobs.sh` (15 проверок, включая инъекции).

Задание с деплоем кода (`git pull` на сервере) очередь НЕ делает
намеренно: она сама этот код и выполняет, и обновлять его тем же
проходом значит менять правила посреди их применения. Деплой остаётся
командой владельца.

## Разовая настройка клона

```bash
git config core.hooksPath tools/githooks    # защита от опасных коммитов
```

Проверить, что защита жива: `bash tools/test_safety.sh`.

## Где считать

- **Песочница** (эта сессия): код, тесты, отрицательные контроли.
  Данных нет — ряды и журналы книг живут на сервере.
- **VPS** `116.203.146.99`: все прогоны, живая торговля, страницы.
  Доступ у ассистента только по HTTP (порт 80, ключ параметром `k=`);
  команды на сервере выполняет владелец.
