# Спека 17 (черновик): бумага как исполнитель — книги по тикам на бумажной бирже

Черновик 2026-10-15 по просьбе владельца (14.10): «перенести бумажную
книгу полностью в лайв: не каждый час пересчитывать, а чтобы сделки
бумажных книг считались по тикам, графики были живыми и пользователи
видели, как исполняются сделки в реальном времени».

Написано человеческим языком: владелец обязан иметь возможность
оспорить каждое правило до кода. **Это отдельный этап после App Store**
(решение 14.10): здесь появляется второй расчёт денег, а именно так
умерла первая версия — поэтому у этапа своя спека, свои проверки и
своя неделя сверки.

## 0. Что уже сделано без этой спеки (путь 1, 14.10)

Прогон длинных книг идёт каждые 5 минут (тёплый прогон 47 с), коротких
— каждые 15 (145 с), общий счёт — следом (30 с); публикация в git —
раз в час. Отметка открытых — раз в 10 с по живой цене. Исполнение
внутри часа видно в приложении через минуты, а не через час; ядро одно.
Спека 17 нужна, когда минут мало, а нужны секунды.

## 1. Что строим и чего не строим

**Строим** бумажную биржу для живого исполнителя (`bot ladder`): тот же
код, что ведёт позиции на Bybit, ведёт их на бумаге — по живой ленте
сделок и живому стакану, с заявками, частичными исполнениями,
комиссиями и funding. Бумажная книга становится **подпиской на
бумажную биржу**: решения приходят теми же намерениями, что у живых
подписок, касса считается тем же правилом (депозит + своё
реализованное), журнал пишется тем же писателем, приложение и сайт
читают его теми же маршрутами, что живые позиции (`positions`,
`trades`, пуши).

**Не строим** второй движок правил: входы, рунги, цели, полы, срок —
по-прежнему решает бумага часового цикла (`run_d6.plan_position` →
намерения), исполнитель только исполняет уровни. **Не трогаем**
пересчёт по записи (`ladder.py`, `run_paper.py`): он остаётся
бэктестом и инструментом исследований.

## 2. Бумажная биржа — правила исполнения (объявлены до кода)

Все правила — те же, что в «Чего не делать» проекта и в спеке 14 §5.

| событие | правило |
|---|---|
| лимитная заявка (рунг, цель) | исполняется, когда ПРИНТ ленты проходит СКВОЗЬ цену заявки (сделка по цене лучше или равной с противоположной стороны); касание стакана не считается; объём — по объёму принтов до полного заполнения (частичные исполнения допускаются) |
| рыночная / IOC (вход, выход) | проходом по живому стакану: заполняется уровнями до нужного объёма, средняя цена — взвешенная по уровням; потолок в б.п. от середины — как у живого исполнителя (не влезло — остаток не исполнен, повтор следующим тактом) |
| стоп пола | срабатывает по ПОСЛЕДНЕЙ цене принта (как у Bybit с LastPrice); исполняется как рыночная проходом по стакану |
| ликвидация | по цене ликвидации позиции (формула площадки, таблица maintenance margin) — закрытие по стакану, минус комиссия ликвидации |
| комиссии | тейкер / мейкер по справочнику площадки на момент сделки |
| funding | по ставкам площадки (ряды сборщика), на открытую позицию в моменты расчёта |
| мин. лот и мин. нотионал | как у площадки; меньше — заявка не ставится, и это записано |
| задержка | исполнитель видит ленту с задержкой сборщика (≈ 1 с); отдельная «латентность» не моделируется — это и есть реальная |

Чего бумажная биржа НЕ моделирует и это сказано на странице: очередь в
стакане на своей цене (наш лимит считается исполненным сквозным
принтом — оптимистично для мейкера), влияние своего объёма на рынок
(позиции бумаги мелкие), отказы API биржи.

## 3. Устройство

- **Лента** — у сборщика (`collect.py`) все принты и стакан всех имён
  уже в памяти каждую секунду. Он отдаёт их наружу локальным потоком
  (unix-сокет или `/feed` на 8765: принты и срезы стакана по подписке
  на имена). Второго подключения к бирже не заводится.
- **Один процесс на все бумажные книги** — `bot paper`: N экземпляров
  логики `ladder.rs` (по ячейке) в одном процессе с одной бумажной
  биржей (`PaperVenue: Venue`). 72 процесса по 60–80 МБ на 7.7 ГБ не
  поместятся; один процесс — цель ≤ 300 МБ, считается переписью.
- **Решения** — намерения из часового цикла, как у подписок
  (`intents.py`): каждая ячейка — бумажная подписка с депозитом и
  форматом; касса — правило подписки.
- **Журнал** — тот же формат §7.6 спеки 15; сверка с пересчётом —
  числом, как `vs_paper` у живых (вход, выход, разный исход, прочее).

## 4. Запись и честность

- **Бэктест** (вся история до дня перехода) — пересчёт по записи, как
  сегодня. **Вперёд** со дня перехода — бумажная биржа. Это две части
  одной кривой, посчитанные по-разному; страница и приложение называют
  день перехода и говорят это словами. Запись вперёд семейств начинается
  заново с этого дня (`FAMILY_SINCE`), как при любой смене правил.
- До перехода — **неделя тени**: бумажная биржа ведёт те же решения
  параллельно с пересчётом, расхождение печатается по частям (вход,
  выход, исход) и по кассе. Переход — решением владельца по числам, а не
  по календарю.
- Пересчёт по записи не исчезает: на нём стоят исследования, он
  воспроизводим; бумажная биржа воспроизводима только вперёд.

## 6. Решения владельца

1. Очередь на своей цене: исполнять лимит по сквозному принту (оптимистично) или требовать, чтобы через цену прошёл объём больше нашей заявки (строже, ближе к реальности).
2. Какие ячейки ведутся по тикам: все 72 или только сложный процент (36) — память и наглядность.
3. Неделя тени — обязательна перед переходом, или переход по первым дням при малом расхождении.
