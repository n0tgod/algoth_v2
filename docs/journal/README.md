# Журнал сессий

Зачем: у ассистента нет памяти между сессиями, у репозитория есть.
`CLAUDE.md` держит **состояние** («что мы знаем сегодня»), журнал
держит **хронологию** («что спросили, что ответили и почему решили
так»). Разделение не формальное: состояние читается каждой сессией
целиком и потому обязано быть коротким, а хронология читается по
необходимости и потому может быть подробной.

## Формат записи

Один файл на месяц: `ГГГГ-ММ.md`. Внутри — записи сверху вниз по
времени, каждая по шаблону:

```
## ГГГГ-ММ-ДД · роль · короткое имя шага

**Владелец:** что спросил или попросил (своими словами, сжато).
**Сделано:** что именно изменилось — файлы, прогоны, числа.
**Почему так:** довод, по которому выбран этот путь.
**Почему не иначе:** что рассматривалось и было отвергнуто, с доводом.
**Осталось:** открытые концы, если есть.
```

Раздел «почему не иначе» обязателен, когда решение можно было принять
двумя способами. Он и есть главная ценность журнала: через месяц
никто не вспомнит, почему выбрали одно, и разбор пойдёт по второму
кругу.

## Когда писать

- владелец принял решение или изменил направление;
- получен результат прогона, меняющий картину;
- найден дефект класса «отказ, неотличимый от тишины»;
- отвергнута идея — с доводом, чтобы она не вернулась молча.

Не пишутся: ход правок, зелёные тесты, промежуточные шаги. Для этого
есть `git log`.

## Чего в журнале быть не должно

Ключей, секретов, паролей — никогда, даже в примерах (правило
`docs/DATA-SAFETY.md`). Полных выгрузок логов — вместо них числа и
ссылка на отчёт в `out/`.
