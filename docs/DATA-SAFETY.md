# Сохранность данных — жёсткие правила

Этот файл — не пожелание, а список запретов. Он появился потому, что
записанное правило само по себе НЕ защищает: за историю проекта данные
терялись пять раз, и каждый раз правило уже было записано где-то в
памяти. Поэтому здесь рядом с каждым запретом стоит механизм, который
его исполняет.

Читать: любой сессии, перед первым коммитом и перед любой командой,
которая пишет на диск сервера.

## 1. Классы данных — и что о них надо знать

**Класс A. Невосстановимо ничем.** Потеря окончательна.

- запись стакана и ленты B1 (`research/b1_book/out/<символ>/…`) —
  архива стакана не существует нигде, ни у Binance, ни у Bybit;
- журнал живого исполнителя (`bot/out/live/…`) — это история сделок
  реальными деньгами, восстановить её можно только частично и только
  из биржевого API;
- журналы решений книг (`research/s8_loop/out/model*/picks.jsonl`,
  `review.jsonl`, `entries_live.jsonl`, `exits_live.jsonl`) — модель
  приняла эти решения в тот момент времени, заново их не принять;
- журнал листов сечения (`sheets.jsonl`) — то же самое.

**Класс B. Восстановимо дорого** (часы работы, трафик, деньги за VPS).

- свечи и funding (`research/*/out/…` вне git) — перекачиваются часами;
- хранилище A2 (Parquet) — пересобирается из свечей;
- веса моделей — переобучаются циклом за час.

**Класс C. Восстановимо дёшево.** Артефакты прогонов, отчёты, кеши,
сводки — пересчитываются кодом из данных классов A и B.

**Правило класса:** любая команда, которая может тронуть класс A,
выполняется только по явной просьбе владельца и только после того, как
названо, что именно будет затронуто. Класс B — с предупреждением о
цене восстановления. Класс C — свободно.

## 2. Запреты

1. **`rm -rf` по каталогу с данными класса A или B — никогда.**
   Удалять можно поимённо, увидев, что удаляешь (`ls` перед `rm`).
   Так уже терялись артефакты F1: чистка `rm -rf out` перед коммитом.
2. **`git add -A` / `git add .` — запрещены.** Только явные пути. С
   машины, где артефактов нет на диске, `-A` записывает их УДАЛЕНИЕ, и
   следующий `git pull` на сервере стирает их и там. Так терялись
   артефакты F1 и манифест L2. `tools/publish.sh` использует
   `--ignore-removal` и не вправе публиковать удаления никогда.
3. **`git checkout -- <файл>` для отката правки — запрещён.** Он
   сносит ВСЕ незакоммиченные изменения файла, а не только вашу
   последнюю правку. Для отрицательных контролей: копия в scratchpad,
   возврат копией.
4. **Архивация журнала с открытыми позициями — запрещена.** Живой
   исполнитель проверяет это сам (`tools/run_live.sh` отказывается,
   `journal_rules_guard` в ядре отказывается); обходить отказ флагом
   `--archive-with-open` можно только по явной команде владельца.
5. **Переименование каталога модели вместо каталога книги —
   запрещено.** Каталог `model` — это каталог МОДЕЛИ (веса, векторы,
   история IC), а не книги. Отставлять книгу умеет только
   `archive_book`; ручное `mv` уже роняло живой контур.
6. **Ключи бирж — только в `~/.bybit/live.env` на сервере (режим
   600).** Никогда в git, в код, в логи, в отчёты, в scratchpad и в
   переписку. `.gitignore` содержит `*.env`; ключ страницы наблюдения
   живёт в `out/token.txt` и в git не идёт.
7. **Прерывать прогон, который пишет на диск, — только после того,
   как понятно, что он пишет.** Сборщик на TERM дожимает часовые
   файлы; убийство `-9` посреди записи оставляет недописанный член
   архива.

## 3. Механизмы, которые исполняют правила

- `tools/safety_check.sh` — проверка перед коммитом: удаления в
  защищённых путях, маркеры конфликта, ключи, крупные файлы. Ставится
  git-хуком: `git config core.hooksPath tools/githooks` (разово в
  каждом клоне — и в песочнице, и на сервере).
- `tools/publish.sh` — единственная команда публикации артефактов;
  `--ignore-removal`, отказ на маркерах конфликта, повторы при сетевых
  сбоях.
- `tools/run_live.sh` — отказ архивировать живой журнал с открытыми
  позициями.
- Сторож `tools/watchdog_book.sh` — предупреждение о диске по
  СВОБОДНОМУ месту (12 ГБ), потому что заполненный диск не замедляет
  запись, а обрывает её.

## 4. Чего у нас всё ещё НЕТ, и это честно названо

**Резервной копии записи стакана не существует.** Данные класса A
живут в одном экземпляре на томе сервера. Отказ диска или ошибка
`rm` уничтожат недели записи. Варианты, между которыми выбирает
владелец:

1. снапшоты тома у Hetzner — просто, платно (около 20 % стоимости
   тома), восстановление минутами;
2. второй том и суточный `rsync` — дешевле, но тот же датацентр;
3. выгрузка закрытых суток на внешнее хранилище (Storage Box) —
   надёжнее всего, требует настройки и трафика.

Пока не выбрано ни одно — риск потери недель записи существует и о нём
надо помнить при каждой операции с диском.

## 5. Порядок при опасной операции

1. Назвать словами, что будет затронуто и к какому классу относится.
2. Показать состояние ДО (`ls`, `df`, число строк, размер).
3. Сделать копию, если класс A или B и копия помещается.
4. Выполнить.
5. Показать состояние ПОСЛЕ и сверить с ожиданием числом, а не
   впечатлением.

Шаг 5 не формальность: сборка A2 однажды отчиталась «42 партиции»
вместо 78, потому что сводка писала дельту прогона, а не состояние
диска.
