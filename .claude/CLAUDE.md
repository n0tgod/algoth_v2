# graphify — граф кода вместо чтения файлов (решение владельца 2026-10-21)

Граф кода проекта лежит в `graphify-out/` (вне git; хук начала сессии
`tools/graphify_setup.sh` собирает его из кода за ~3 мин в фоне, ход —
`graphify-out/build.log`). Это дополнение к карте `docs/MAP.md`, не замена.

Правила:
- Есть `graphify-out/graph.json` — вопрос о коде начинается с `graphify query "<вопрос>"`, а не с grep и чтения файлов; то же правило — в задание каждому субагенту, который ходит по коду. Файл читается только там, где граф или прошлое чтение уже назвали строки.
- Связь двух мест — `graphify path "<A>" "<B>"`; одно место — `graphify explain "<имя>"`; кто пострадает от правки — `graphify affected "<имя>"`; узлы-хабы — `graphify god-nodes`. Ответы — обрезанный подграф, обычно много меньше grep.
- `graphify-out/GRAPH_REPORT.md` — только для обзора архитектуры, когда query/path/explain не дали контекста.
- После правки кода — `graphify update .` (AST, без модели, минута). Графа нет (хук ещё строит или сети нет) — работать по `docs/MAP.md` и грепом, как раньше: граф — ускоритель, не условие.
- Сервер graphify не знает и не запускает: очередь заданий, сторож и публикация его не касаются. Ключей и записи в графе нет — `.graphifyignore` исключает `research/*/out`, `jobs/`, журналы и память.
